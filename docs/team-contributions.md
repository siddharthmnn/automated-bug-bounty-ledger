# Team Responsibilities

The work is divided into two equal areas of responsibility for planning and demonstration. This describes the agreed ownership split; it does not replace the implementation history recorded in Git commits and pull requests.

## Siddharth Menon — database and backend

- Relational database design and schema migrations.
- Keys, constraints, indexes, views, stored procedures and triggers.
- MySQL roles, grants and backend database access.
- API routes, server-side services and business logic.
- Qdrant integration, embedding generation and vector synchronization.
- SQL analytics implementation and backend validation.

## Tanisha D — frontend, integration and validation

- Frontend walkthrough and user-facing application flows.
- Researcher and administrator interface review.
- Application integration and end-to-end workflow validation.
- Unit, integration and manual acceptance evidence.
- Responsive and accessibility review.
- DBMS demonstration material, screenshot organization and project documentation.

## Shared work

Both members contribute to requirements, design decisions, integration, debugging, final testing and the project demonstration. Each member should be prepared to explain the complete workflow at a high level and their primary technical area in detail.

## GitHub record

Use the repository's commit and pull request history as the source for individual implementation attribution. Do not infer authorship of an entire subsystem from the responsibility split above.
